### 안 켜져 있던 다섯 사이트 — 코드 문제가 아니에요

Playwright 로 **확장프로그램을 실제로 띄워서**(`--load-extension`) 확인했어요.

- 다섯 사이트 모두 content.js 가 끝까지 돌아요 (예외 없음, `__mmDebug` 생성됨)
- K Car 에서 패널이 쓰는 `mm-status` 에 정상으로 답해요
  (`{site:'kcar.com', armed:false, showing:false}`) → **스위치가 비활성이라는 의심은 틀렸어요**
- 저장소에 `mmOn:kcar.com=true` 를 넣으면 바로 위장 화면이 떠요

즉 켜기만 하면 되는 상태였어요. 남는 설명은 **위장 화면의 ⏻ 를 눌러 꺼졌을 가능성**이에요.
⏻ 는 ⚙ 바로 옆이고, 확인도 되돌리기도 없이 그 사이트를 꺼 버려요. 그 뒤로는 그냥
원래 화면만 보여서 껐다는 사실조차 알 수 없어요. 그래서 끈 뒤 6초 동안 '되돌리기'를
보여주도록 고쳤어요.

### 사람인이 목록을 상세로 보던 이유

범인은 **기업 카드 안의 '진행 중 공고' 미니 목록**이었어요. 줄마다 `입사지원` 버튼이
붙어 있는데, 그 줄들은 `findCards` 가 카드로 세지 않아서 "카드 안의 버튼은 뺀다"는
기존 보정에 걸리지 않았어요.

```
button.sri_btn_sm > div.job_date > li > ul.list_ongoing > div.item_corp
```

사람인이 이 블록을 그릴 때만 상세로 튀어서, 같은 주소인데 될 때도 있고 안 될 때도
있었어요(실제로 세 번 돌리면 한 번꼴). 잡코리아 검색도 '즉시 지원'으로 같은 증상이
있었어요.

**고친 방법**: 구매 버튼이 *남의 줄*에 붙어 있으면 빼요. 버튼에서 6칸 위까지 올라가며,
그 덩어리가 이 페이지 제목과 상관없는 제 이름(10자 이상인 링크 글)을 달고 있으면
남의 줄이에요. 이 페이지 제목을 품은 덩어리를 먼저 만나면 이 페이지 것이고요.

먼저 '같은 버튼이 줄마다 반복되면 목록'이라는 규칙을 넣어 봤는데, 사람인 공고 상세의
추천 목록까지 걸려서 상세를 못 알아봤어요. 제목과의 관계를 보는 쪽이 맞았어요.

| | 고치기 전 | 고친 뒤 |
|---|---|---|
| 사람인 검색 (3회) | 상세로 오인(들쑥날쑥) | 목록 40~45줄, 3회 모두 정상 |
| 사람인 직업별 목록 | 상세로 오인 | 목록 78줄 |
| 잡코리아 검색 | 상세로 오인 | 목록 23줄 |
| K Car 검색 | 목록 | 목록 26줄 (그대로) |
| 사람인 공고 상세 | 상세 | 상세 (제목·보낸이 정상) |
| 상품 고정 페이지 | 상세 | 상세 ('구매하기') |

쿠팡은 Playwright 를 막아서(Access Denied) 상품 상세를 못 쟀어요. 쿠팡 구매 바처럼
제목과 멀리 떨어진 버튼이 있으면 이 규칙에 걸릴 수 있으니, 실제 확장으로 한 번
확인해야 해요.

### 항공권 (트립닷컴, 서울→도쿄)

`findCards` 가 카드 8장을 **전부 진짜 목록에서** 잡았어요. 날짜별 최저가 띠(15개)도
필터의 항공사별 가격(14개)도 잡지 않았어요. 목록을 찾는 건 문제가 아니에요.

| 칸 | 읽은 값 |
|---|---|
| 단가 | `136800` ✅ |
| 품목 | `에어부산` — 항공사가 제목 자리에 (노선·편명이 아님) |
| 거래처 | `에어부산저비용 항공사` — 배지가 붙어 한 덩어리 |
| 납기 | `null` — `15:35`·`18:10` 을 못 읽음 |

car/job 둘 다 아니라 쇼핑 칸으로 떨어져요. 항공편 칸(거래처=항공사 · 품목=노선 ·
출발 · 도착 · 소요 · 경유)이 따로 필요하고, 왕복은 한 줄에 두 구간이라 칸 구조를
처음으로 비틀게 돼요. 목록 자식은 32개인데 8장만 읽혀요(화면에 보이는 만큼).

스카이스캐너는 봇 확인 화면, 네이버 항공권은 브라우저 도구가 열지 못해 못 쟀어요.

## 함께 고친 공통 문제

- 이전 패치에서 정규식의 단어 경계(`\b`)가 보이지 않는 제어 문자로 들어가, 영어 날짜('Nov 15'), 'today/tomorrow', 'was $…' 가격 이름표, '4.5 out of 5' 평점이 읽히지 않던 문제를 고쳤어요.
- 화면 낭독용 칸 이름('상품명', '가격정보', '판매가', '할인율')은 제목·판매자 후보에서 빼요.
- 여러 줄에 같은 글이 판매자로 반복되면(기획전 이름, 배지) 다음 줄이나 제목 첫 단어로 바꿔요.
- 글의 첫 %가 카드 할인·적립률일 때가 있어, 원래 가격과 지금 가격으로 셈한 할인율과 크게 다르면 셈한 값을 써요.
- '머리말 메뉴' 판정을 좁혔어요. 이름에 header만 들어간 본문 칸(Target 'productDetailHeader') 안의 구매 버튼도 이제 상세 화면 신호로 써요.
- 사이트 정렬은 가격·판매·추천 같은 상품 정렬 말이 있는 묶음만 가져와요 (리뷰 정렬 제외).
- (아침) 구매 버튼 판정: 카드 목록·캐러셀·꼬리말(페이지 아래쪽 절반) 안의 버튼은 빼요.
- (아침) 카드 안 링크가 지금 페이지와 같은 주소면 상세 주소가 아니에요. 주소 없는 카드는 줄을 누르면 원래 카드를 대신 눌러요.
- (아침) 옛 라이브러리(prototype.js)가 배열 함수를 바꿔 둔 사이트(엔카)에서도 돌게, 배열 함수의 셋째 인자를 쓰지 않아요. 실제 확장프로그램은 따로 떨어진 공간에서 돌아서 원래 영향이 없어요.

## 아직 남은 것

- 화면에 보이는 것만 그리는 목록(NOL 숙소)과 스크롤해야 더 불러오는 목록(AliExpress, 아고다)은 처음에 보이는 만큼만 읽혀요.
- 정렬 메뉴가 열기 전에는 페이지에 없는 사이트(무신사, 29CM, 아고다)는 사이트 정렬을 못 가져와요. 이때는 기존의 우리 정렬을 써요.
- 실제 확장프로그램으로 꼭 확인할 것: 11번가 미리보기(다른 주소에서 읽어 오기), 쿠팡 미리보기, K Car처럼 주소 없는 카드 누르기.

- 사이트가 개편되면 읽는 방식이 어긋날 수 있어요. 알려 주면 그 사이트를 다시 시험해서 고쳐요.
